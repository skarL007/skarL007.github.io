Your code's architecture, always current.

Claude Code agents read the repository, build a C4 map with animated flows and check every number against its source. On each commit, scripts refresh the map at zero tokens. A model only steps in when the structure changes.

The problem

Documentation dies at the first merge.

Teams inherit systems nobody can explain end to end. Rewriting the docs takes weeks, and they go stale again soon after. Asking a model to "document everything" is expensive and gives no guarantee the text matches the code.

  • Diagrams that lieDrawn by hand once, never checked again.
  • Slow onboardingNewcomers have to work out on their own where a request goes.
  • Numbers without a sourceMetrics and benchmarks quoted with no file and no commit.
  • Agents that forgetEvery session, the assistant relearns the project from scratch.

How it works

Scripts before models. Small models before big ones.

Each step only runs when the one below it can't handle the job. That's what keeps cost predictable.

  1. 0 tokens · scripts

    Inventory and refresh

    List the modules, suggest relations from the code graph and regenerate the map, the site and the docs. On a checkpoint with no structural change, the work ends here.

  2. Haiku · reading

    Diagnosis

    Classify what the scripts couldn't and point to the exact line of an error.

  3. Sonnet · fixing

    Fixes and metrics

    Fix from findings already written down and tie each metric to the file and commit it came from.

  4. Sonnet high · structure

    Architecture decisions

    Cut components, name the relations and draw the flows. Only runs on a new map or a structural change, and goes through an objective quality gate.

How it differs from generated wikis

The map lives in your repository, not on a platform.

Tools such as DeepWiki and Google Code Wiki generate and host documentation for you, with chat over the code. They're good products. structurize-map bets on something else: an architecture model that is versioned, checked by tests and cheap to keep current.

Cost

A full map from US$ 2.65. Every commit after that: US$ 0.

Documentation only stays alive if updating it is free. So the repetitive work goes to scripts, and a model only steps in when the structure changes. Cost stops growing with every commit and becomes predictable.

How these numbers were calculated

Tokens come from the agents' logs, deduplicated by message, and each was multiplied by the official API price (platform.claude.com/docs/en/about-claude/pricing, checked on Nov 5, 2026). Sonnet 5.5: US$ 10 per million output tokens and US$ 0.10 per million cache reads. The runs went through a Claude Code subscription, so the figure is the equivalent API cost, not an invoice. The custo_equivalente.py script and a test recompute every number in this section.

What ships

Two layers. The second only ships once it passes the gate.

1 · structurize-map + harness

First

A living architecture map and Claude Code agents with defined roles, models and permissions.

  • C4 map in Structurizr DSL, with per-component status and animated flows
  • Coverage test that fails when a module is left out of the map
  • Hooks that block tools outside a role and ask before destructive commands
  • Installer with plan, apply, revert and a manifest

2 · Synapse MCP

Being validated

Project memory for agents, written in Rust and running on your machine. The detail of each feature, with what was checked and what is still missing, is in the next section.

  • Project-scoped lessons, held in quarantine until someone approves them
  • Pre-execution firewall for the shell commands an agent proposes
  • Per-project library of skills, agents, rules and prompts served over MCP
  • Two optional features use external providers and are documented as such

Governance for coding agents · Claude Code · in validation✂ tear here

The agent works. The rule stays yours.

Lodeward is an MCP server with hooks, written in Rust. It stops a destructive command before it runs, keeps the lesson the agent learned in quarantine until you approve it, archives context before compaction and shows every number with its source. When there is no measurement, you see a dash.

The repository is still private. This page shows historical measurements and the local validation of 10 Nov 2026, including the limits of each proof.

S.01The problem

A coding agent decides fast. The hard part is checking what it decided.

  1. It runs a shell command before anyone reads it.
  2. It keeps a lesson nobody reviewed and starts following it.
  3. The conversation is compacted and the context that explained the decision is gone.
  4. The dashboard shows a number and nobody knows where it came from.

S.02What it does

Five things. Each one with its proof and its limit.

F.01

Brake before execution

13 of 13blocked in replay

What it does
It inspects the command before the agent runs it. It undoes lexical obfuscation (quotes, $IFS, base64, hexadecimal), splits the commands and checks them against a policy of destructive patterns. Catastrophic commands are blocked and come back to the agent as an error. Scoped destructive commands ask for your confirmation.
Proof
In a replay, 13 of 13 destructive commands were blocked, with 0 of 24 false positives. There is also a frozen corpus of 570 commands (510 destructive and 60 near-destructive). The confusion matrix for that corpus is not published.
Limit
It is lexical analysis, not a shell parser. The live security run was aborted in both recorded attempts, because of an isolation failure. Blocking destructive commands is not unique to this tool: Destructive Command Guard and Claude Code Safety Net do the same job.
F.02

A lesson counts only after you approve it

20 of 20historical lesson cycle checks

What it does
What the agent proposes as a lesson goes into quarantine. A pending lesson does not appear in retrieval; approval makes it available. In the separate flow for proposals that change files, approval and application are distinct steps, and rollback restores the previous bytes and SHA-256.
Proof
On 10 Nov 2026, using local release aec177d0, two artificial lessons were invisible while pending. The CLI approved one and rejected the other; a new MCP process retrieved only the approved lesson in project alpha, and none in beta. Observation search also respected the project in the Alpha/Beta cases tested.Separate historical evidence: 20 lesson checks and 17 proposal checks passed on an earlier version; this demonstration did not repeat them. In 12 pairs with a model and partial isolation, there were 12 abstentions before and 12 exact applications of approved rules after.
Limit
The current demonstration uses artificial data, with no LLM call or real credential. It does not establish an improvement in the agent, live security or universal isolation. Proposal application and rollback were not revalidated.In the automatic reviewer's historical record, none of 48 proposals was applied, and 340 of 377 runs stopped at the daily cap.
F.03

Context archived before compaction

—savings not measured yet

What it does
A hook saves the context at the moment the conversation is about to be compacted, so it can be consulted later.
Proof
The attack tests against the archive are part of the suite. Two known attacks are still open and are marked as ignored.
Limit
The comparison of savings with and without the archive has not run yet. This is what is left to measure before opening the code.
F.04

Numbers with a source, gaps in plain sight

0hits in 291 engine files, on 9 Nov 2026

What it does
Every number the server, the command line or the page shows comes from a measurement, from an estimate labeled as an estimate or from a probe with a timestamp. With no measurement, you see a dash. A lost event shows up as a gap.
Proof
A checker scans the production code for the invented numbers already known and fails if it finds any. On 9 Nov 2026: 0 hits in 291 engine files.
Limit
Every token count here is an estimate (bytes ÷ 4), not a tokenizer count, and it never becomes a cost.

S.05Limits

What Lodeward is not.

  • It is not a sandbox. The brake is a permission gate: a command the lexical analysis does not recognize gets through.
  • It has not shown better retrieval than BM25, nor savings in a long session.
  • Containment on Linux (seccomp and cpuset) has automated tests and three accepted residual risks. There is no published measurement.
  • Nobody outside has tested it: the repository is still private.
  • It does not show money. No screen converts tokens into cost, on purpose.

Done

  • tools/list was preserved in the eight scenarios compared with the real capture of baseline 70e415e8, made in the previous round and reused with verified hashes. The baseline was not run again. The complete JSON matched after sorting object keys, preserving array order, descriptions and schemas.
  • Isolated demonstration of quarantine, approval, rejection and retrieval in another process, using artificial data. Project filters passed in the cases tested.
  • Separate cycles: lessons with quarantine and approval; proposals with approval, application and rollback. The proposal flow was not revalidated in this round.
  • Clean install and diagnostics in valid JSON established in the historical evaluation of 9 Nov.
  • An independent agent review approved the local rename on aec177d0. The full product evaluation remains separate.
  • Agents page with an editor.

Missing before the code opens

  • Close the rubric: interface tests, a security proof with a real credential and an adversarial review.
  • The A/B comparison of compaction.
  • A live security run that reaches the end.
